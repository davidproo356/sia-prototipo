# Guía de colaboración

**main es la rama inicial.** No se crean ramas para los compañeros antes de asignar tareas.

1. Leer README y los archivos de docs/ correspondientes al módulo.
2. Actualizar main localmente.
3. Al comenzar una tarea, crear una rama, por ejemplo feature/mobile-home, feature/backend-api, feature/ai-ocr o docs/actualizacion.
4. Hacer commits cortos y descriptivos: docs:, chore:, feat:, fix:, test:.
5. Publicar la rama y abrir Pull Request hacia main con resumen, pruebas y pendientes.
6. Solicitar revisión a otro integrante antes de integrar.

## Acuerdos de equipo
- No subir .env reales, tokens, archivos personales o datos de terceros.
- No llamar detección real o navegación funcional a una simulación.
- Acompañar cada nueva característica con documentación y pruebas.
- Registrar cambios importantes de arquitectura en docs/decisiones/.
- Evitar añadir dependencias o cambiar contratos sin consultar al equipo.
